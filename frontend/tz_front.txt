Техническое задание (ТЗ)

Frontend-часть волонтёрской платформы

⸻

1. Общая информация

Название проекта: Волонтёрская платформа (рабочее название)

Цель frontend-части:
Создать удобный, доступный и масштабируемый пользовательский интерфейс для веб-платформы, обеспечивающий взаимодействие волонтёров, организаций и администраторов с backend-системой.

Frontend должен:
	•	обеспечивать удобную работу на десктопе и мобильных устройствах;
	•	корректно взаимодействовать с REST API backend;
	•	быть готовым к расширению функционала;
	•	учитывать требования доступности (UX/UI).

⸻

2. Типы пользователей и интерфейсы

2.1 Волонтёр

Доступный функционал:
	•	регистрация и авторизация;
	•	заполнение и редактирование профиля;
	•	просмотр списка проектов;
	•	фильтрация и поиск проектов;
	•	просмотр карточки проекта;
	•	подача заявки на участие;
	•	просмотр статусов заявок;
	•	история участия в проектах;
	•	получение уведомлений;
	•	просмотр новостей платформы.

2.2 Организация

Доступный функционал:
	•	регистрация и авторизация;
	•	заполнение профиля организации;
	•	создание и редактирование проектов;
	•	управление статусами проектов;
	•	просмотр заявок волонтёров;
	•	подтверждение / отклонение заявок;
	•	добавление отчётов по проектам;
	•	просмотр статистики по своим проектам;
	•	получение уведомлений.

2.3 Администратор

Доступный функционал:
	•	вход в административную панель;
	•	управление пользователями;
	•	управление организациями;
	•	модерация проектов;
	•	управление категориями и регионами;
	•	управление новостями;
	•	просмотр аналитики и статистики;
	•	блокировка и разблокировка аккаунтов.

⸻

3. Основные страницы и модули

3.1 Публичная часть
	•	Главная страница
	•	описание платформы;
	•	преимущества;
	•	CTA-кнопки (“Стать волонтёром”, “Для организаций”);
	•	Страница проектов
	•	список проектов;
	•	фильтры: регион, категория, формат, дата;
	•	поиск по названию;
	•	Карточка проекта
	•	описание проекта;
	•	организация;
	•	даты и формат;
	•	кнопка «Подать заявку»;
	•	Новости
	•	список новостей;
	•	страница отдельной новости.

⸻

3.2 Авторизация и регистрация
	•	Регистрация волонтёра;
	•	Регистрация организации;
	•	Авторизация;
	•	Восстановление пароля;
	•	Валидация форм;
	•	Сообщения об ошибках.

⸻

3.3 Личный кабинет волонтёра
	•	Профиль пользователя
	•	персональные данные;
	•	навыки и интересы;
	•	статистика часов;
	•	Мои заявки
	•	список заявок;
	•	статус каждой заявки;
	•	История участия
	•	Уведомления

⸻

3.4 Личный кабинет организации
	•	Профиль организации;
	•	Мои проекты;
	•	Создание / редактирование проекта;
	•	Заявки волонтёров;
	•	Отчёты по проектам;
	•	Статистика.

⸻

3.5 Административная панель
	•	Dashboard (общая статистика);
	•	Пользователи;
	•	Организации;
	•	Проекты;
	•	Новости;
	•	Категории и регионы;
	•	Логи активности.

⸻

4. UX / UI требования
	•	Адаптивная верстка (desktop / tablet / mobile);
	•	Поддержка современных браузеров;
	•	Интуитивная навигация;
	•	Минимальное количество действий для целевых сценариев;
	•	Использование дизайн-системы (UI-kit);
	•	Поддержка светлой / тёмной темы (желательно);
	•	Доступность (WCAG 2.1 — базовый уровень).

⸻

5. Работа с API
	•	Взаимодействие через REST API;
	•	Хранение access token (JWT);
	•	Обработка ошибок (401, 403, 404, 500);
	•	Loading / empty / error states;
	•	Централизованный API-клиент;
	•	Возможность масштабирования под GraphQL.

⸻

6. Технологические требования (рекомендуемые)
	•	Framework: React (Next.js) или Vue (Nuxt);
	•	Язык: TypeScript;
	•	State management: Redux Toolkit / Zustand / Pinia;
	•	UI: MUI / Ant Design / Tailwind + Headless UI;
	•	Form handling: React Hook Form / VeeValidate;
	•	HTTP client: Axios / Fetch;
	•	Локализация: i18n (задел);
	•	Тестирование: базовые unit-тесты (опционально).

⸻

7. Безопасность
	•	Защита приватных роутов;
	•	Ролевая маршрутизация;
	•	Проверка прав доступа на UI уровне;
	•	Logout при истечении токена.

⸻

8. Нефункциональные требования
	•	Быстрая загрузка страниц;
	•	Code splitting;
	•	SEO (для публичных страниц);
	•	Чистая структура проекта;
	•	Документация по запуску и сборке.

⸻

9. Результат работы frontend-разработчика
	•	Готовое веб-приложение;
	•	Подключение ко всем backend API;
	•	Адаптивный интерфейс;
	•	README с инструкцией по запуску;
	•	Подготовка к дальнейшему масштабированию.

⸻

10. Перспективы развития
	•	Мобильная версия / PWA;
	•	Мультиязычность;
	•	Интеграция с мобильным приложением;
	•	Улучшенная аналитика;
	•	Расширение личных кабинетов.

⸻

Frontend должен быть реализован с расчётом на рост платформы до национального уровня и использование большим количеством пользователей.
